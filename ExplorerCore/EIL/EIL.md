# Краткий обзор Explorer Implementation Library (EIL)

**EIL** — это легковесная внутренняя библиотека, состоящая из высокопроизводительной системы событий и строго типизированной системы управления настройками. Оба компонента поставляются только в виде заголовочных файлов (header-only), избегают использования макросов и ориентированы на минимальные накладные расходы.

## 1. EIL Event System (Система быстрых событий)

Легковесная реализация событий, оптимизированная для быстрого добавления и удаления обработчиков, а также минимизации выделения памяти.

**Ключевые особенности:**

* **Современный C++:** Поддержка move-only объектов благодаря `absl::AnyInvocable`. Отказ от `std::function`, макросов, базовых классов и RTTI.
* **Оптимизация памяти:** Использование `absl::InlinedVector` позволяет хранить первые несколько обработчиков прямо в объекте события, избегая аллокации в куче.
* **Высокая скорость:** Подписка выполняется за время **O(1)**. Отписка использует метод *swap-and-pop* (поиск за O(n), удаление за O(1)), что исключает сдвиг элементов в памяти.
* **Возвращаемые значения:** При использовании событий с типом возврата выполняются все обработчики, но возвращается результат только **последнего**.

**Основы использования:**

* **Подписка:** При передаче функции или лямбды возвращается объект `event_token`.
* **Вызов:** Метод `.invoke(args)` вызывает все зарегистрированные обработчики.
* **Отписка:** Осуществляется передачей токена обратно в объект события (например, `ValueChanged(token)`).
* **Потокобезопасность:** Отсутствует (требуется внешняя синхронизация).

## 2. EIL Settings (Система настроек)

Система управления конфигурацией с автоматической сериализацией в JSON (на базе библиотеки Glaze) и нулевым количеством шаблонного (boilerplate) кода.

**Ключевые особенности:**

* **Строгая типизация:** Настройки объявляются как обычные C++ переменные (`eil::single_threaded_rw_setting`). Нет необходимости искать значения по строковым ключам, что дает проверку типов на этапе компиляции.
* **Ленивая загрузка и кэширование:** JSON-файл считывается только при первом обращении к настройке. Все последующие чтения происходят из кэша в памяти (скорость **O(1)**).
* **Умное сохранение:** Отслеживаются только измененные (dirty) значения. Сохранение происходит атомарно (сначала во временный файл) при вызове `write_changes()` или деструкции объекта.
* **Уведомления об изменениях:** Встроенная система событий позволяет подписываться на изменения конкретных параметров.
* **Совместимость:** Поддержка стандартных типов, контейнеров (векторы, мапы), пользовательских типов Glaze, а также `winrt::hstring` и UTF-16.

**Основы использования:**

* **Структура:** Класс настроек наследуется от `eil::settings_base`.
* **Доступ:** Чтение и запись выглядят как обычное присваивание (`settings.Theme = L"Dark"`).
* **Хранение:** Несколько классов настроек могут автоматически сосуществовать в одном JSON-файле (по умолчанию `settings.json`), каждый в своей секции.
* **Потокобезопасность:** Рассчитано на однопоточный доступ.
